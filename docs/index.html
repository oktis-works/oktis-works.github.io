Documentação do OkCMS

Bem-vindo à documentação oficial do OkCMS, o CMS moderno, multi-tenant e extensível da Oktis Works.

1. Instalação

O OkCMS é um monorepo baseado em Bun. Clone o repositório e instale as dependências:

git clone https://github.com/oktis-works/cms.git
cd cms
bun install

Configure as variáveis de ambiente (banco de dados, Redis, segredos JWT) e rode as migrações:

cp .env.example .env
# edite o .env com suas credenciais
bun run db:migrate
bun run dev

2. Primeiros passos

Após iniciar o servidor, acesse o painel administrativo em http://localhost:3011/admin e crie seu primeiro tenant. O OkCMS cria o tenant default automaticamente no primeiro bootstrap.

Criar uma coleção

No admin, vá em Collections → Add Collection, defina o nome (ex.: posts) e adicione campos (texto, rich text, imagem, data, etc.).

Consumir via API

Os dados ficam disponíveis em /api/v1/collections/{nome} com autenticação via JWT ou API Key.

curl -H "Authorization: Bearer SEU_TOKEN" \
  https://api.seudominio.com/api/v1/collections/posts

3. Plugins

Plugins estendem o OkCMS com novos tipos de campo, admin components e integrações. Cada plugin precisa de um manifest.json declarando:

  • namenome, versão, tipo
  • compatibility.okcmsrange semver validado em tempo de carga
  • fieldTypes[]tipos de campo customizados
  • permissionspermissões necessárias no manifesto

Exemplo de manifesto mínimo:

{
  "name": "meu-plugin",
  "version": "0.1.0",
  "type": "plugin",
  "compatibility": { "okcms": "^0.40.0" },
  "fieldTypes": [],
  "permissions": []
}

O loader do plugin valida a compatibilidade antes de importar o ponto de entrada, evitando que plugins incompatíveis quebrem o sistema.

4. Temas

Temas são construídos com Astro e definidos em theme.json. Eles podem herdar layouts de temas pais e isolam CSS por componente.

  • layouts[] — layouts oferecidos pelo tema
  • assets[] — CSS/JS publicados
  • stylesConfig — engine de CSS e ponto de entrada

Exemplo de theme.json:

{
  "name": "default",
  "version": "0.40.0",
  "type": "theme",
  "compatibility": { "okcms": "^0.40.0" },
  "provides": { "layouts": ["page-home", "post", "single"] },
  "stylesConfig": { "engine": "css", "entry": "src/theme.css", "output": "dist/theme.css" }
}

5. Referência rápida da API

Método Endpoint Descrição
POST /api/v1/auth/login Autentica e retorna JWT
GET /.well-known/jwks.json Chaves públicas JWKS para validação de JWT
GET /api/v1/collections/:nome Lista itens de uma coleção
POST /api/v1/collections/:nome Cria item na coleção

Todas as requisições mutantes exigem autenticação via Authorization: Bearer <token> e respeitam o contexto de tenant da sessão.

6. Implantação

O OkCMS roda em containers Docker. Bancos suportados: PostgreSQL (principal), MySQL 8.0.36+ e MariaDB 11.4+.

  • API: apps/api — servidor Hono
  • Admin: apps/admin — SPA Astro servido estaticamente pela API em produção
  • Web: apps/web — site público
  • Worker: apps/worker — fila de jobs (imagens, e-mails, eventos)

Variáveis críticas: DATABASE_URL, REDIS_URL, JWT_SECRET, ENCRYPTION_KEY, EXPOSE_POWERED_BY=false.
