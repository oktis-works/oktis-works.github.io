Boas Práticas

Recomendações de segurança, desempenho e operação para rodar o OkCMS em produção com confiança.

🔐 Segurança

+

Contexto de tenant rígido

Nunca use conexões sem tenant definido. O OkCMS remove o contexto global de fallback; acessos fora de establishTenantContext() lançam erro, evitando vazamento entre tenants.

+

RLS (Row Level Security)

Todas as tabelas multi-tenant têm RLS habilitado. Aplicações nunca devem desabilitar RLS globalmente; use SET LOCAL row_security = off apenas dentro de transações administrativas explícitas.

+

Cookies seguros em produção

A função validateProductionConfig() rejeita inicialização com cookies sem Secure, SameSite=Strict ou JWT_SECRET padrão. Não pule essa validação.

+

CSRF com protocolo obrigatório

Entradas em TRUSTED_ORIGINS devem incluir protocolo (https://). Host-only é rejeitado para evitar bypass.

+

CSP e X-Powered-By

O X-Powered-By está desativado por padrão (ativa só via EXPOSE_POWERED_BY=true). A API envia Content-Security-Policy: default-src 'none'.

⚡ Desempenho

+

Rate limiting com Redis

Use armazenamento Redis (sorted sets com TTL) para limitação de taxa. Há fallback em memória apenas quando Redis está indisponível — não depende dele em produção.

+

Cache com tags

Use invalidação por tag (entity:123, collection:posts, tenant:abc) em vez de chaves brutas.

+

Worker de fila separado

Processos pesados (redimensionamento de imagem, e-mails, eventos) rodam no apps/worker, não na API principal.

🛠 Operação

  • Banco: use PostgreSQL com SSL em produção. MySQL e MariaDB são suportados, mas Postgres é o primário.
  • Migrações: sempre rode o teste de aceitação de upgrade (postgres-upgrade-acceptance.mjs) antes de aplicar novas versões.
  • JWT: assine com RS256, use kid e exposta as chaves públicas em /.well-known/jwks.json. Habilite rotação de chaves com período de graça.
  • Logs: não escreva senhas, tokens ou chaves em logs. Use estruturados (JSON) para facilitar ingestão em observabilidade.
  • Monitoramento: acompanhe a DLQ (dead_letter_events) e replaie eventos falhados manualmente após corrigir a causa.
